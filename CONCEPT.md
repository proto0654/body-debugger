# Body Debugger — Концепция приложения

> Десктопное приложение в системном трее для айтишников.  
> Напоминает встать и сделать короткую разминку, ведёт учёт прогресса и визуально показывает трансформацию персонажа.

**Статус:** Концепция зафиксирована  
**Последнее обновление:** 2026-10-28  

Документация разработки (граф, English): [docs/CONTEXT.md](docs/CONTEXT.md) · [docs/README.md](docs/README.md). Этот файл — источник правды по продукту; не переводить машиной.

---

## 1. Суть и философия

Приложение живёт в трее и минимально отвлекает.  
Главный принцип: **один попап = одно упражнение**.  

Всё остальное (статистика, персонаж, вес, фото, AI, инвентарь, предпочтения) — опциональные слои, которые не ломают основной цикл.

---

## 2. Ключевой цикл взаимодействия

```
Триггер (таймер / долгий idle / окончание события)
        ↓
Трей-иконка меняет состояние
        ↓
Мини-попап у трея с ОДНИМ упражнением
        ↓
[Сделать] [Отложить] [Пропустить]
        ↓
Если «Сделать» → таймер (обязателен в Medium+)
        ↓
Фиксация результата + опциональные данные
        ↓
Обновление стрика, стадии/ветки персонажа, статистики
        ↓
Трей возвращается в норму
Следующий триггер считается от момента завершения
```

---

## 3. Уровни строгости фиксации

| Уровень   | Поведение                                                                 | По умолчанию |
|-----------|---------------------------------------------------------------------------|--------------|
| Soft      | Кнопка «Готово» активна сразу                                             | Нет          |
| Medium    | Таймер обязателен. «Готово» только ближе к концу. Закрытие = `skipped`   | **Да**       |
| Hardcore  | Medium + удержание кнопки + редкие дополнительные проверки                | Нет          |

### Статусы сессии
- `done` — выполнено
- `snoozed` — отложено
- `skipped` — сознательно пропущено (можно указать причину)
- `missed` — не было реакции

---

## 4. Три уровня интерфейса

### Трей
Единственный постоянный элемент.  
Состояния: спокойно / скоро / надо встать / только что сделал / стрик.

Правый клик: Пауза, Дашборд, Настройки, Выход.

### Попап (~320×220 px)
- Название и описание упражнения
- Таймер
- Кнопки «Отложить» и «Готово»
- Сворачиваемый блок (по умолчанию скрыт): повторы, ощущения, вес, фото

### Дашборд
Три вкладки:
- **Сегодня** — стрик, персонаж, прогресс, следующее напоминание
- **Календарь** — heatmap + детализация по дням
- **Статистика** — графики, распределение по зонам, уровни упражнений

---

## 5. Система персонажа (универсальная)

Приложение хранит только абстрактные значения:

- `characterStage`: 0–5
- `characterBranch`: `neutral` | `posture` | `power` | `mobility`
- `characterBuild`: `lean` | `average` | `stocky` | `neutral` (опционально)

### Стадии
| Стадия | Ключ     | Смысл                  |
|--------|----------|------------------------|
| 0      | start    | Скуф / начальное       |
| 1      | awake    | Проснулся              |
| 2      | moving   | Разминается            |
| 3      | steady   | В тонусе               |
| 4      | strong   | Крепкий                |
| 5      | peak     | Desk Hulk / пик        |

### Ветки
- `posture` — акцент на осанке (шея, спина, плечи)
- `power` — силовая / ударка / инвентарь
- `mobility` — растяжки, йога, подвижность
- `neutral` — баланс

### Билд (персонализация)
Задаётся при онбординге или в настройках:
- Худой (`lean`)
- Обычный (`average`)
- Плотный (`stocky`)
- Пропустить

Влияет на стартовый внешний вид и на то, как выглядит прогресс.  
Приоритет картинки: `stage + branch + build` → `stage + branch` → `stage` → эмодзи.

Персонаж полностью заменяемый. Логика от визуала не зависит.

---

## 6. Пользовательские предпочтения (Focus)

В настройках пользователь указывает, что ему ближе. Это даёт бонусы к весам при выборе упражнений и влияет на ветку персонажа.

### Направления
- Mobility / Растяжки / Йога
- Лёгкая атлетика
- Силовая (верх, отжимания, корпус)
- Пояса и части тела
- Ударка
- Баланс

Можно выбрать основное направление + дополнительные акценты.  
Предпочтения **смещают вероятности**, но не отменяют чередование зон и штрафы за недавнюю нагрузку.

## 7. Логика выбора упражнений

### Группы
- **Upper** — шея, плечи, верх спины, запястья
- **Lower** — бёдра, ноги, низ спины
- **Full** — общее, кор
- **Equipment** — мешок, груша и т.д. (если включено)

### Правила
- Штраф за группу/категорию из предыдущей сессии
- Штраф за то, что уже делалось сегодня
- Бонус давно не использованным или отстающим зонам
- Бонусы от пользовательских предпочтений
- Учёт инвентаря и текущего уровня упражнения

Режимы: Баланс (дефолт), Ротация, Фокус, Дожим.

---

## 8. Модель данных (ключевые сущности)

### Exercise (строгая схема)
```ts
{
  id: string
  title: string
  description: string
  durationSec: number
  difficulty: 1 | 2 | 3 | 4 | 5
  category: string
  equipment?: string[]
  imageKey?: string
  emojiFallback: string          // обязательно
  modificationOf?: string
}
```

### Session
- status: `done` | `snoozed` | `skipped` | `missed`
- exerciseId, длительность
- опционально: reps, feeling, weight, photoIds, skipReason

### UserProgress
- streak (current / max)
- characterStage, characterBranch, characterBuild
- exerciseLevels
- focus (primary + accents)
- настройки (строгость, интервал, инвентарь, тема и т.д.)

---

## 9. Нейронка (опциональный слой)

- Анализирует статистику, предпочтения и историю.
- Может предлагать новые упражнения, усложнения или временную корректировку приоритетов.
- Возвращает данные **только** в формате валидного `Exercise`.
- Пользователь должен явно утвердить предложение.
- Без AI приложение полностью работоспособно.
- Нет картинки → используется `emojiFallback`.

---

## 10. Опциональные возможности

- Вес и фото прогресса
- Учёт повторов и субъективных ощущений
- Домашний инвентарь (мешок 50 кг, боксёрская груша и др.)
- Разные темы оформления
- Разные персонажи
- Экспорт данных

Все опциональные функции включаются/выключаются и не влияют на основной цикл.

---

## 11. Архитектурные принципы

1. Один попап — одно упражнение.
2. Основной цикл максимально короткий.
3. Предпочтения смещают, но не ломают ротацию.
4. Прогресс персонажа считается из данных.
5. Визуал (тема + персонаж) полностью заменяемый.
6. Обязательные фолбэки (эмодзи, работа без AI и т.д.).
7. Валидация всех внешних данных.
8. Локальное хранение как основа.
9. Опциональные слои не могут сломать ядро.

## 12. Дефолтный персонаж

**Офисный Халк (Desk Hulk)**  
Сутулый офисный работник в худи, который постепенно превращается в собранную и мощную версию себя.  
Поддерживает биллы: Lean / Average / Stocky.

### Ассеты (текущий сет)
Расположены в `assets/character/desk-hulk/`:

- `sprite-sheet-stages.png` — чистый лист прогрессии (стадии × биллы)
- `sprite-sheet-branches.png` — позы под ветки (нейтральная / power с мешком / mobility)
- `emotions/emotions-set-1.png` — базовые эмоции (устал / довольный / сосредоточенный)
- `emotions/emotions-set-2.png` — расширенные эмоции (зевота, радость с жестом, серьёзность)
- `emotions/emotions-set-3.png` — дополнительные реакции (рука на лбу, довольный, задумчивый)

Рекомендуется нарезать на отдельные файлы по схеме `stage-{n}-{build}.png`, `pose-{branch}.png`, `emotion-{name}.png`.

## 13. Анимации интерфейса (текущий этап)

Полноценная анимация персонажа откладывается на перспективу. На текущем этапе используются микро-анимации интерфейса и смена статичных спрайтов с эмоциями.

### Трей
| Состояние       | Анимация                          |
|-----------------|-----------------------------------|
| Спокойно        | Статичная иконка                  |
| Скоро           | Мягкая пульсация                  |
| Надо встать     | Заметная пульсация + лёгкое покачивание |
| Успех           | Короткий «прыжок» + вспышка       |
| Стрик           | Лёгкое свечение                   |

### Попап
- **Появление**: выезд + лёгкий scale и fade (150–200 мс).
- **Таймер**: круговой или линейный прогресс. Последние секунды — усиленная пульсация.
- **Успех (`done`)**: анимация кнопки, вспышка, смена эмоции персонажа на «довольную», плавное исчезновение.
- **Пропуск**: быстрый fade-out без акцента.

### Эмоции персонажа
Даже на статичных картинках эмоция меняется через crossfade + лёгкую анимацию:

| Событие              | Эмоция              | Дополнительно          |
|----------------------|---------------------|------------------------|
| Открытие попапа      | Нейтральная / фокус | Появление              |
| Во время таймера     | Сосредоточенная     | —                      |
| `done`               | Довольная           | Bounce                 |
| Длинный стрик        | Гордая              | Лёгкое свечение        |
| Много пропусков      | Устал / раздражён   | —                      |
| Повышение стадии     | Удивлённая → довольная | Более заметная смена |

### Дашборд и достижения
- Появление персонажа: fade + подъём.
- Повышение стадии: вспышка + надпись «Новая форма».
- Увеличение стрика: pop-эффект на числе.
- Heatmap: появление ячеек с небольшой задержкой.
- Кольцо прогресса: анимированное заполнение.

### Принципы
- Большинство анимаций — 150–300 мс.
- Сильные акценты только на важные события (стадия, длинный стрик, первое выполнение за день).
- В настройках есть пункт «Уменьшить анимации».
- Ничего не блокирует работу дольше 1–1.5 секунд.

### Что заложить в реализацию
- Enum состояний трея + CSS-анимации.
- Компонент персонажа принимает `stage + branch + build + emotion` и умеет плавно менять картинку.
- Набор базовых микро-анимаций (fade, scale, bounce, pulse).
- События: `onSessionDone`, `onStageUp`, `onStreakMilestone` и т.д.
